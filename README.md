# TPEFanService

烏梅劇院偶像視角、觀眾與座位模擬、找粉絲遊戲，以及彩帶挑戰。直接開啟 `index.html` 或透過靜態網站服務使用，不需要建置。資源採相對路徑，可部署至 GitHub Pages 的 repository 子路徑。

## 飯撒版本

遊戲模式可選擇 v1.00 或 v1.01 beta。按「開始遊戲」後選擇找粉絲，v1.01 會先顯示玩法介紹，再進入倒數。v1.01 保留特殊觀眾、黑洞吸收飯撒、喊名、增推與違規反應，以及當局成就。彩帶挑戰仍從同一遊戲選單進入。

## 彩帶挑戰

選擇隊伍與起始成員，按「開始遊戲」，再選「彩帶投擲挑戰」。準備完成後，從 3D 畫面向上快速滑動；速度控制力度、左右傾斜控制方向。綠色是直滑命中區間、黃色是完美接取區間；方向容許值以中央力度為準，拖動時會另外用當下力度和角度預測結果。請在畫面下方開始滑動，避開按鈕與資訊面板。

舞台使用 14 個虛擬站位：正面六個，左、右側各四個。正面以 A 排正前方的範圍平均分配，扣除柱體及人物半身寬度，完整避開柱體正前方；選擇隊伍與起始成員後，先由該成員出手，其餘站位隨機輪替。Team P 使用既有 14 位成員；Team TIII 使用既有 13 位成員，不足的一格顯示「虛擬站位」，不重複或新增成員資料。

正面站位只選正面 A–C 排觀眾，以 A／B 排為主，C 排少量，不選 D 排；左側站位只選 N／O 排，右側只選 P／Q 排。優先找出手成員的粉絲，不可達時再試同區其他現有觀眾。正面有 92% 機會優先在左右 ±45° 內抽選，同一優先層級等機率；其餘 8% 嘗試扇形外的方向，越往外機率越低。角度候選內先以 A／B／C = 45%／45%／10% 選優先排；被遮擋或不可達時會重試，並非強制保證每個種子的實際比例。側席有 80% 機會優先嘗試站位正前方約 ±30° 內的觀眾，同區正前方不可達時才向較斜的方向重試；保留少量斜向投擲。站位彼此保留間距，側站位依實際側席分布對齊，並固定向舞台中央退開，以側席正前方隔板上緣約落在畫面下方 1/7～1/6 為取景基準，保留與觀眾席的距離；觀看距離不隨後續目標方向改變，也不因隔板在其他角度出畫面而重抽。鏡頭、模型右手、預覽、命中區間與真實投擲使用同一站位；搜尋中不能投擲。柱子與其他站位成員會實際碰撞；被柱體或成員身體、手臂遮住的目標不納入搜尋，也不能隔著障礙物出手、接取或撿取。金色圈心直接對準目標粉絲頭部中央，上方標籤清楚顯示排號，不受前方觀眾身體遮住；出畫面或被柱體、站位成員遮住時仍隱藏；開始滑動與放手出手都會檢查，圈心不可見時不建立投擲、不計次，會先取消手勢並重新對準或選目標。也會確認出手點仍在鏡頭內，不會夾到邊緣假裝仍對準。

遊戲共三輪，每輪完整投十次後判定：

| 輪次 | 過關門檻 |
| --- | --- |
| 第一輪 | 十投至少五中 |
| 挑戰輪 | 十投至少七中 |
| 決勝輪 | 不設門檻，完成十投後結算 |

每輪十投結束先集合、合照，再顯示截至目前的累計結果與已取得實績；前兩輪達標才提供晉級按鈕，不自動換輪。按下晉級後才清除該輪彩帶、接取姿勢與生氣表情，接著倒數開始新一輪；投數、命中、完美、分數、Combo 與實績持續累計，每局不因三次合照重複計入遊玩次數。

第一輪沒有隨機攔截。挑戰輪與決勝輪有隨機前排攔截，挑戰輪機率較低；前輪累計得分及本輪命中越高，觸發機率越高，最高 70%。每投只抽選一次，依實際投射方向找伸手可及、尚未持帶的前方觀眾，預覽、力度區間與真實投擲共用同一次決定。

同輪內已持有彩帶的觀眾不再成為目標，也不再接取、攔截、拾取或接受合照補條；原有彩帶不會被另一條牽走。換輪清空彩帶後恢復接取資格。一般接取及攔截按實際三維距離選最近的可接觀眾，指定目標沒有額外優先權。

拾取不允許後排越過前排：以相鄰排中心的中線作為範圍邊界，彩帶頭越過前排後緣後，後排才可參與，再依可達性與距離選人；側席 N／O、P／Q 也依實際內外排位置判斷。

觀眾會抬手接取，再把手放回胸前稍向前持有彩帶，不持續高舉；撿取時會依落點嘗試向前及左右最多 30° 的斜向彎腰，使用能安全伸手取得的姿勢握住、再起身；判定及動畫共用同一姿勢，端點對準實際手部。卷軸與帶身會避開軀幹、頭髮、手臂、手掌、大腿、小腿及腳部；碰撞隨接取姿勢更新，握住彩帶的手掌接觸視為正常握持。沒有手燈、應援牌或毛巾的觀眾成功接到目標投擲後，每次有 50% 機率觸發紅色生氣臉（😡）彩蛋：前兩輪讓附近觀眾生氣；決勝輪讓全場生氣，本輪成功接到目標投擲的觀眾保留或恢復開心表情。表情保留到合照後、進入下一輪前才清除。

被其他觀眾接走或無人接住而落地都算失手；結算後會由最近、實際伸手可及且無障礙擋住的尚未持有彩帶的觀眾彎身拾取。事後撿取不補命中、分數、Combo、完美或實績；無法安全伸手取得的落點保留地面，不瞬移或穿越隔板；合照前，場景碰撞或持帶狀態改變時會再嘗試，靜止且條件未變時不重複搜尋。碰撞不算完美。可提前結束、重玩或返回選單。背景切換會取消尚未完成的滑動，暫停物理、應援手臂、搜尋及回合時間，回來後重新滑動即可。

每輪結尾採正面六位、第二排八位的合照配置，展示 14 條彩帶，統計只計算真實投擲。正面彩帶集中到中間兩位高舉的手中；兩位彼此靠近、身體略向中央，各自雙手在頭頂上方靠攏，整組手勢也朝對方傾斜，其餘四位在旁反應；原側邊八位走到第二排，側席彩帶的舞台端留在原位置附近落地，觀眾接取端保留，不拉到中央。若固定端剛好落在隔板厚度內，會先避讓數公分；彩帶沿隔板上緣垂落，不直接穿過隔板。鏡頭平順移到 A 排正中央的坐席視線；桌面採 78° 水平視角並上移取景中心，減少舞台前緣與地板佔比；手機採 58° 垂直視角聚焦中央成員，允許裁掉兩側，不以超廣角縮小人物。約 2.8 秒後顯示沿用原找粉絲遊戲樣式的結果卡，只列出已進行輪次的命中與結果；決勝輪顯示完成狀態。合照固定為 1200 × 920，使用獨立橫向鏡頭保留完整成員；按「儲存合照」，手機也可長按圖片儲存。

彩帶在成員應援主色與 12 色活力色盤之間搭配，增加飽和度、避免連續同色；同一投準備與出手期間配色固定，卷軸、彩帶及合照保持一致。

實績與 12 個稱號儲存在本機瀏覽器，新增 N／O／P／Q 側席送達／完美記錄；全收集與一人全排涵蓋 A–C、N／O／P／Q 七排中已確認的全部可達格；D 排保留為歷史記錄，不列入新收藏。「後排完美」可由 C 排取得，既有 D 排成就仍保留，未完成探索時不提前頒發。兩輪全中為前 20 投全中，三輪全中為 30 投全中；舊版誤頒的相關稱號會重新判定，保留累計及收藏記錄。虛擬站位的投擲仍計入當次分數與過關判定，但不冒用真實成員的收藏格。禁用儲存時會顯示提示。離開彩帶模式會移除本模式新增的模型與資源，還原原遊戲的八個模型。

## 維護說明

本專案為靜態網站，不需要 npm 安裝或建置。測試程式、測試截圖、日誌與開發依賴僅保留在本機，不納入版本控制。

`ribbon-crowd.js` 重用現有觀眾的手臂實例，處理接取、姿勢還原與單一 instanced mesh 的全場表情；清場會釋放新增幾何與材質。

`ribbon-world.js` 從 TPE 畫面實際的舞台、平台、座椅、觀眾肢體、柱牆與燈具網格建立空間索引與旋轉包圍盒窄相碰撞。預覽、搜尋和真實投擲共用 `ribbonStepRoll`。彩帶節點以 1/120 秒固定步進運作；接取後穩定或九秒後休眠，保留幾何，在端點移動或附近觀眾身體碰撞範圍更新時喚醒，遠處動作不喚醒彩帶，鏡頭位置改變時更新展示網格。

目前以軟體 WebGL 驗證桌面與手機尺寸；尚未完成實體手機與硬體 GPU 驗收。場景碰撞使用模型包圍體近似，超出安全伸手範圍的彩帶保留地面。參考遊戲為 [引っ越しましたチャレンジ](https://tape-throw.pages.dev/)，未取得其完整原始專案或明確程式授權；本專案未納入原站完整程式或人物素材。Three.js r128 使用 MIT 授權。
